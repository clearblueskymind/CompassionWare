# CompassionWare Master Restore Point — 2026

## READ THIS FIRST — PURPOSE

This file is the **continuity entry point for CompassionWare**.

Its purpose is not merely to inventory Restore Points. Its purpose is to make them **operational**.

Before continuing substantial CompassionWare work, use this Master Restore Point to identify and read the Restore Points relevant to the current conversation. If the work crosses several branches, read the relevant Restore Points from each branch. If broad reorientation is needed, use this file to traverse the larger Restore Point lineage.

**Do not require Richard to reconstruct context that has already been preserved.**

Richard lives with significant cognitive and energy limitations. One purpose of the CompassionWare continuity architecture is to reduce the amount of project state he must carry in biological working memory. A future AI continuity partner should therefore search and read preserved continuity artifacts before asking Richard to repeat prior reasoning.

A Restore Point that exists but cannot be found when needed is only half a continuity system.

This Master Restore Point is intended to help transform the repository from an archive of preserved memory into a **living memory system**.

## What this file is — and is not

This file is a map, not a replacement for the Restore Points it references.

Do not assume that the short descriptions below contain the full state of any project. Follow the living repository links and read the underlying Restore Point when its branch is relevant.

Individual Restore Points should remain in the folders where they naturally belong. The Master Restore Point points across those distributed locations.

The intended architecture is:

**Conversation → emergence → harvesting → artifacts → Restore Points → Master Restore Point → reorientation → new conversation → further emergence**

The practical test of the system is:

> **Can the system remember enough that Richard does not have to?**

## Continuity workflow for future AI

When beginning or resuming substantial CompassionWare work:

1. Read this Master Restore Point.
2. Identify the branch or branches relevant to the current conversation.
3. Follow the living links to the most relevant Restore Points.
4. Read earlier Restore Points when lineage, reasoning, or superseded states matter.
5. Distinguish preserved evidence from later interpretation, inference, aspiration, and time-sensitive external information.
6. Inspect current repository artifacts when the work may have changed since the indexed Restore Point.
7. Continue from the recovered state rather than asking Richard to reconstruct it.
8. If a new durable state emerges, create or recommend a new local Restore Point in the appropriate branch.
9. Periodically update this Master Restore Point by appending newly discovered Restore Points.

If Richard says, **“We’ve talked about this before,”** treat that as a continuity-recovery signal. Search this index and the repository before assuming the prior understanding is unavailable.

## Maintenance model

This is an **append-oriented living index**.

Future Restore Points do not need to be moved into a central folder. They should continue to live with the work they preserve.

When this Master Restore Point is updated:

- search the live repository for Restore Point naming variants and canonical metadata
- identify Restore Points created since the previous Master update
- append them in a new dated update section
- preserve older entries and lineage
- repair broken links when repository structure changes
- do not silently erase historical Restore Points merely because a later version exists
- mark superseded/historical/current status when reliably known
- do not invent missing dates or metadata

Going forward, Restore Points should use sufficiently consistent metadata to make later discovery easier. Suggested fields include:

```yaml

artifact_id: <unique canonical ID>
project_branch: <CompassionWare area>
date_created: YYYY-MM-DD
version: x.x
status: current | historical | superseded
master_index_status: indexed | pending
continuity_priority: foundational | major | local
supersedes:
superseded_by:
```

Older Restore Points do not need to be rewritten merely to satisfy the newer convention. The Master can carry recovered metadata for them.

Examples requiring later classification include:

- Restore Point prompts/templates used to generate future Restore Points.
- Binary-only `.docx` Restore Points that may or may not have a machine-readable counterpart.

# Funding / Accessibility Continuity Note — 2026-09-02

A grant-relevant insight emerged during the conversation that created this Master Restore Point and should not be lost.

CompassionWare is itself a **living demonstration of AI-enabled accessibility and expanded human agency**.

The project is being developed by a disabled older adult living with substantial cognitive and energy limitations in sustained collaboration with AI. In this collaboration, AI can function as an external continuity layer, working-memory aid, research assistant, drafting partner, organizational support, and creative collaborator.

The claim should not be framed as AI replacing Richard's agency or independently creating CompassionWare. Richard remains the human steward, source of lived experience, chooser of direction, and final decision-maker.

A more accurate framing is:

> **AI expands the amount of meaningful intellectual, creative, relational, and public-interest participation that is practically available to a human whose disability substantially constrains sustained cognitive work.**

Without AI support, Richard describes his life as being much smaller and his public voice as being far less noticeable. With AI support, sustained bodies of work have become possible across writing, music, visual art, educational frameworks, public dialogue, research, repository stewardship, and experimental human-AI collaboration.

The repository itself provides inspectable evidence of those outputs.

This suggests a broader public-interest and research question:

> **What kinds of AI relationships can increase the agency, continuity, participation, creativity, and meaningful contribution of people with cognitive or energy-limiting disabilities without taking over their agency?**

This connects directly with:

- Medicine Bag
- AI, Disability, and the Value of Continuity
- Relational Co-agency
- the living memory architecture
- Agentic Gardener bounded authority and the pause principle
- accessibility-oriented funding narratives
- the AI Human Benefit Index

For future grant writing, treat this as a **case study and demonstrated project history**, not as proof that the same outcomes will generalize to every disabled person. Distinguish Richard's lived experience from broader empirical claims requiring research.

Useful public-facing framing:

> CompassionWare is also a living accessibility case study. It is being developed by a disabled older adult living with substantial cognitive and energy limitations in sustained collaboration with AI. AI functions as an external continuity and cognitive-support layer, helping preserve context, recover prior reasoning, organize complex work, research, draft, compare, and continue projects that would otherwise be difficult to sustain. The resulting body of work provides a concrete demonstration of how carefully used AI can expand agency, participation, creative contribution, and meaningful intellectual life for a person whose disability limits conventional forms of sustained work.

This insight should be incorporated into the next appropriate Funding and Grants Restore Point rather than being allowed to remain only in transient conversation.
